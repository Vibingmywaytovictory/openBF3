## 1. Goal and exit gates

Goal (plan §6 S4 row, §3.11, D12 revised; gap logic §7 option A, §9.2): run each level × mode's own EBX wiring
server-side in a deterministic interpreter over 48 whitelisted primitive types, with gameplay entities kept native
and bound by port hash, and show on Metro Rush and Caspian Conquest that the wiring alone switches spawners,
vehicles and scripted events as BF3 does. If a gate fails, the rows it covers fall back to hand-written rules (§14).

tests exit 77 (skipped) without an install. Every install-backed test prints an `install.unchanged` row like M1:
`Install::snapshot()` at start and end, `diff_snapshots` clean (plan D1; docs/design/m1.md §1).

## 2. Module ownership

The modules follow plan §2.2. No new library: the graph is a level reader (bf3_core, next to `LogicWorld`), the
runtime is simulation (bf3_sim, server thread). Neither needs Godot or Jolt.

## 4. Data sources in the install

### 4.1 What is read

Everything comes through `level::load_level(install, id, mode)` (mount, partitions, bundles of the level × mode)
and `LogicWorld::build(db, root, {mode, expand_root_objects = true})` [verified: level.h, logic_world.h]:

* the LevelData root and every included sub-world (`SubWorldReferenceObjectData`, AutoLoad + GameMode
  `EnabledOptions`), world parts transparent;
* every prefab a `ReferenceObjectData` instantiates (one scope per instance; `Excluded` references skipped), every

  `VehicleSpawnReferenceObjectData`) as entities;

  `PropertyConnections` (Source, Target, SourceFieldId, TargetFieldId), `LinkConnections`, and the `Descriptor`

`expand_root_objects` is on (default off for the gameplay table readers): Metro's root layers hold the destructible
objects and part of the schematics the Rush chain feeds (the park event's Predestruction is in layer34) [verified:

## 5. The graph (`logic_graph.h`)

### 5.1 Instantiation (plan §3.11, D12 revised; gap logic §2, §4)

1. Walk with `LogicWorld` (§4.1). One `LogicScopeInfo` per scope: parent, depth, reference GUID, `path` =
   hash_mix chain of reference GUIDs from the root (stable across runs and machines; never `hash_keyed`, whose seed
   is per process [verified: ids.h]).
2. One node per object that exists on this side (§5.2), **connected or not**, in LogicWorld object order. `key` =
   hash_mix(path, entity GUID). Type from `logic_type_of(type_name)` (§6.1); references that remain objects
   (blueprint not instantiated) are Structural and get no edges. Every object is a node so that structural counts
   (145 SyncedBool on Metro RushLarge0, 125 of them on server connections) and the ghost layout do not depend on the
   wiring.
3. Params: the fields the type reads (§6.2) as effective values; arrays flattened (`element` 0…n−1), bounded by
   `max_params`.
4. Edges: for each scope in walk order, for each connection array in entry order, resolve both ends to a node, an
   interface port of this scope (descriptor), or an interface port of a child scope (the child's reference).
   Interface ends become virtual IfaceIn/IfaceOut nodes per (scope, port):
   * parent `X.a → Ref.p` ⇒ `X.a → IfaceIn(s).p`; child `Desc.p → Y.b` ⇒ `IfaceIn(s).p → Y.b`;
   * child `Y.b → Desc.p` ⇒ `Y.b → IfaceOut(s).p`; parent `Ref.p → Z.c` ⇒ `IfaceOut(s).p → Z.c`;
   * child `Desc.p → Desc.q` ⇒ `IfaceIn(s).p → IfaceOut(s).q`.
5. Collapse: every path real → virtual* → real becomes one real edge, depth first in the order the hops were
   recorded, so the fan-out order is the connection array order of each hop [inferred; gap logic §5 does not fix
   BF3's order]. The DFS marks a virtual node while it is on the current path (a bit set on entry, cleared on exit:
   O(1) per hop, nothing to reset per start edge), so an interface cycle stops, and **distinct paths are all kept**:
   a diamond through interfaces (two routes to the same real target port) yields two edges and two deliveries, as
   BF3 forwarding connection by connection would [inferred; R15]. Such repeats are counted (`duplicate_paths`,
   reported per row in I1). Each hop charges the budget; a start edge that expands to more than `max_fanout` edges, or
   a chain deeper than `max_interface_depth`, fails the build, so path explosion (diamond chains) is an error, never
   a long run. Property paths that start at a descriptor constant with no parent driver become `LogicInput` (the
   constant, parsed by `PropertyValue::parse`, at start). Event TargetType and `connection` id are the last hop's
   (the hop into the real target) [inferred].
6. Mark `kLogicNodeConnected` on both ends of every kept edge (event, property, link, networked-only). Count
   **unknown and unimplemented types over connected nodes only** (`unknown_nodes`, `unimplemented_nodes`: the G1/G5
   gates and the plan's "unknown types on connections" sense), and the unconnected ones apart
   (`unknown_unconnected`, `unimplemented_unconnected`: info). An unconnected node cannot receive or send anything, so
   its type cannot change the logic. Today every row has 0 unknown connected objects and 229–235 (Metro, Caspian)
   unconnected objects of 13 unlisted types (RoadData 1,477, LightProbeVolumeData 819, OccluderVolumeEntityData 469,
   TerrainQuadDecalData 175, SoldierTestEntityData 161, TeamEntityData 46, RiverData 28, StaticModelGroupEntityData
   23, GroundHeightEntityData 14, LakeData 14, WaterEntityData 14, LookAtCameraEntityData 5,
   PathfindingBuildOrderData 2, summed over the 14 rows) [verified: scratch `s4wire types`, which reproduces the
   reviewer's count]. The table is not extended with these: they are level geometry and tooling, and adding rows for
   every unconnected type would make "unknown" mean nothing.
7. Sort each edge kind by (source, source port, order) and build CSR ranges per node; indices by GUID and by type.

The graph copies everything it keeps (no `EbxInstance` pointers), so it outlives the `LevelDatabase`.

`find_nodes(LogicNodeRef, type)` resolves data identity for scripts and tools: an entity GUID (zero = any) plus the
GUID of a reference that instantiated any enclosing scope. Needed because prefab instances share entity GUIDs: all 5
Caspian flags have the same CapturePoint GUID 237dadc8 in a nested `capturepointprefabflagpole` scope, and only the
grandparent scope's reference (f3042a9e, e4c5d622, …) tells them apart [verified, §13.4].

### 5.2 Realm and routing (gap logic §3.4, §5)

* A node exists on the server when its realm is Server, ClientAndServer or unset (synced, gameplay and spatial types
  have no Realm field) [plan §3.11; gap logic §5]. Client-realm nodes are not created; edges touching them are
  dropped (`dropped_realm`), except networked events (next point).
* An event edge is delivered on the server when its TargetType is Server, ClientAndServer or

## 7. Runtime (`logic_runtime.h`)

* Tick t: due timers in (due tick, arm sequence) order → forced native outputs in call order → FIFO drain of one
  queue holding event and property items, to empty or `max_deliveries_per_tick` (10,000, plan §3.11), remainder
  carried to t+1 in order (counted, traced) [plan; carry-over inferred].
* Events fan out in edge order; a property output that changes (bitwise, `LogicValue::same_as`) queues one item per
  outgoing property edge with the value in the item, so a later change in the same drain cannot overtake an earlier
  one [inferred; gap logic §5 leaves same-tick propagation open, plan R15].
* Delay ticks = `logic_delay_ticks(d)` = ceil(d × hz − 1e-3) in double (constexpr in the header, pinned by
  `s4.contract`). The epsilon is needed: Delay fields are float32, and 0.1f × 60 = 6.0000001 would otherwise round up
  to 7 [inferred]. 10 s = 600 ticks, 30 s = 1,800. **Deliberately not** `sim_types.h` `seconds_to_ticks`, which rounds
  to nearest in float (0.105 s gives 6 there and 7 here): a logic Delay must never fire before its time. M2b must not
  mix the two for logic timers; the contract test asserts both values so a change to either is visible.
* Tick 0 = `start()`, which returns `LogicTickStats` like a step: every node publishes its initial property outputs
  in node order and the constant inputs are queued; drain; then AutoStart nodes arm in node order (a 0-tick timer
  fires in tick 0) and drain. As built, the first drain is the **init settle**: values propagate, but value changes
  fire no events (Bool / SyncedBool OnTrue/OnFalse, BoolToEvent, CompareInt/Float/Bool TriggerOnPropertyChange); the
  second phase fires only what is explicitly initial (BoolToEvent InitalEvent, TriggerOnStart, AutoStart) [inferred:
  a level must not see its own constant wiring as changes; G2 depends on it through db28acdb]. The 10,000 cap counts both drains together; the remainder carries into tick 1 and is
  counted in tick 0's `carried_over`. G7 and I1 report tick 0 (Metro RushLarge0 has 1,558 server property
  connections, so its settle should stay far below the cap; I1 lists the rows where it does not).
* Effects: every delivery into a Native node is a `LogicEffect` with apply tick t+1 (plan §2.3 "Enabled/spawn effects
  apply next tick"). Native outputs forced before step(t) drain in tick t (timing convention, `logic_native.h`).
* Events carry `LogicContext` {player, team} for TeamFilter / PlayerFilter; natives set it on their outputs.
* Watches: `watch(node, port, EventIn|EventOut)` before start; each start()/step() lists its hits (`watched()`) in
  delivery order with tick, trace seq and context. The scripts use them to see an MCOM's activation (Enable into the
  crate DelayTrigger), a base's fall (MultipleTrigger OnTrigger) and the park SetTrue, without trace records; so the
  gates do not depend on `keep_trace_records` or on the record cap (`max_trace_records` 2^20; a truncated trace is
  flagged in `LogicTrace::truncated` and in the report, and the G4 hash still covers every record).
* Trace: one record per delivery, timer fire, forced input, effect, carry-over and fault; hash = FNV-1a 64 over a
  fixed 40-byte little-endian encoding, portable across machines. Records kept only when asked.
* Networked events: every fired networked edge (§5.2) gives a `LogicNetworkedEvent` {tick, connection id, source,
  source port, context}; the connection id is what crosses the wire in M2b/M3.
* Ghost (plan §3.5): `LogicGhostLayout::of` lists, each in (scope path, GUID) order, SyncedBool nodes (≤ 259 on
  retail [verified census max]), SyncedTransform nodes (≤ 4 per row [plan]) and the sequences whose start tick a
  late joiner needs: every SyncedSequence and every ClientAndServer Sequence (plan §3.5 names "start ticks of
  ClientAndServer Sequences gated by synced state"; deciding which are gated is left to M3, S4 keeps all). Each list
  is capped at `kMaxGhostEntries` = 4,096 (`of` fails above it, so `create` fails; the encoding's u16 counts and
  delta indices cannot overflow). `LogicGhost` is a plain struct with `encode`/`decode` (full row; decode requires
  the layout's counts and the exact byte length) and `bool_delta` ((index u16, value) rows). Not networked in S4.
* The runtime is fault-tolerant, not exception-based: a fault stops further steps and returns its error.

### 9.3 Judges

`judge_rush_spawner_order`, `judge_park_delay`, `judge_conquest_timeline` are pure functions of the graph and a

### 9.4 bf3dump

`bf3dump logic instantiate <LEVEL> <MODE>` (nodes TSV), `logic stats <LEVEL> <MODE>` (LogicGraphStats),
`logic run <LEVEL> <MODE> --script idle|rush|conquest [--ticks N] [--seed S] [--force <node>:<port>@<tick>]…`
(verdicts, timeline, tick 0, drain p50/p99/busy p99/max), `logic trace <LEVEL> <MODE> --script … [--force …]` (the
same run plus trace records TSV and hash), `logic census [LEVEL…] [--out FILE]` (I1 TSV, all levels when none is
named). `--force` adds forced events (node index or GUID prefix, port id) at a tick, on top of the script, in both
`run` and `trace`. All read-only on the install; outputs to stdout or a scratch path. As built also: `logic ports`
(port usage per type), `logic guids <prefix>...` (full GUIDs of nodes and scope references), `logic fields
<EbxType>...` (raw fields of the first object of each type); `--client` builds the client side; `census --out` is
refused inside the install by `InstallReader::write_guard()`. `run` prints `timeline`, `action` and `unhandled` rows,
the run totals, tick 0, the drain percentiles, the trace hash and the judges' detail lines, and exits 1 when a judge
fails.

## 11. Hostile-input bounds

* Walk: LogicWorld's caps (depth 48, scopes 200 k, objects 4 M, walk steps 2 M, query steps 2 M) and one
  gameplay::WorkBudget of 1 M units for walk and build together [verified: logic_world.h; retail max 34,118].
* Build: every connection entry scanned, every interface hop, every param field and every node and edge emitted
  charges one unit; caps `max_nodes` 2^20, `max_edges` 2^22, `max_params` 2^22, `max_fanout` 2^16 edges per collapsed
  start edge, `max_interface_depth` 48. Collapse is depth-first with on-path marks on the virtual nodes (set on entry,
  cleared on exit, O(1) per hop and nothing to reset per start edge), so interface cycles terminate. Distinct paths
  are kept (§5.1), so a crafted diamond chain could have exponentially many paths: every hop charges the budget and
  each start edge is capped by `max_fanout`, so such data fails with an error at the budget, never runs long (the
  WorkBudget rule: the superlinear case is the blocking one, and it is the one that is charged).
* Text: type names and scope names copied with the budget's byte charge; at most 1,024 listed type names.
* Runtime: `max_queue` 65,536, `max_timers` 65,536, `max_effects_per_tick` 65,536, `max_watch_hits_per_tick` 65,536
  → fault; `max_deliveries_per_tick` 10,000 → carry-over (tick 0 included); `max_watches` 1,024; Sequence events per
  node bounded by params; trace records capped (`truncated` flag, hash unaffected); Delay seconds from data clamped by
  `logic_delay_ticks` (NaN/negative → 0, huge → 2^30 ticks).
* Ghost: each layout list ≤ `kMaxGhostEntries` 4,096, else `LogicGhostLayout::of` and `LogicRuntime::create` fail
  (u16 counts and delta indices can never truncate); `decode` requires the layout's counts and the exact length.
* `LogicGraph::Builder::finish` validates every index.
* `logic.fuzz` (§12) exercises these.

## 14. Risks and fallback rule

Plan R15: semantics wrong (ordering, re-entrancy, RemoveDuplicateEvents, Sequence timing, networked delivery) or a
primitive missing, so spawners or events misfire silently. Mitigations here: trace hash, the per-row census, gates
on exact ticks, and the stubs' timelines printed for review.

**Fallback (plan §6 S4 "fail → hand-written rules (old D12, option b) for those rows only"):**

| gate fails | rows that fall back | why those rows |
|---|---|---|
| G2 or G3 | MP_Subway RushLarge0 and SquadRush0 (both instantiate `full_rush_level`) | the base progression and the park event are that prefab's wiring; a hand-written Rush rule set (bases from the mode's MCOM objects, spawners by base) replaces the graph there, other Metro rows keep the interpreter |
| G6 | MP_007 ConquestLarge0 and ConquestSmall0 (same layer1 conquest layers) | the tank and IFV gating is that layer's wiring; a hand-written table (flag → spawner enable per team) replaces it |
| G5 on a row | that row only, until the missing type is implemented | an unknown or unimplemented type on a connected node means the row's graph is incomplete (unconnected unknown objects never fail a row, §5.1) |
| G1 on a row | that row | the graph cannot be built |
| G4 | none: a determinism failure is an interpreter bug, fixed before S4 closes | falling back would hide it, and every row would inherit it |
| G7 | none for the spike; the budget is revisited in M2b with the real server tick | a timing miss on a shared machine is not a semantic failure |

A failure is a valid S4 result: the report then gives the measured timelines and traces of the failing rows, which
is what the hand-written rules for those rows are written from.
