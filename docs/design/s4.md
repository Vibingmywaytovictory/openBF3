## 1. Goal and exit gates

Goal (plan §6 S4 row, §3.11, D12 revised; gap logic §7 option A, §9.2): run each level × mode's own EBX wiring
server-side in a deterministic interpreter over 48 whitelisted primitive types, with gameplay entities kept native
and bound by port hash, and show on Metro Rush and Caspian Conquest that the wiring alone switches spawners,
vehicles and scripted events as BF3 does. If a gate fails, the rows it covers fall back to hand-written rules (§14).

tests exit 77 (skipped) without an install. Every install-backed test prints an `install.unchanged` row like M1:

The modules follow plan §2.2. No new library: the graph is a level reader (bf3_core, next to `LogicWorld`), the
runtime is simulation (bf3_sim, server thread). Neither needs Godot or Jolt.

## 4. Data sources in the install

### 4.1 What is read

Everything comes through `level::load_level(install, id, mode)` (mount, partitions, bundles of the level × mode)
and `LogicWorld::build(db, root, {mode, expand_root_objects = true})` [verified: level.h, logic_world.h]:

* the LevelData root and every included sub-world (`SubWorldReferenceObjectData`, AutoLoad + GameMode
  `EnabledOptions`), world parts transparent;
* every prefab a `ReferenceObjectData` instantiates (one scope per instance; `Excluded` references skipped), every
  ObjectBlueprint reference's Object, spawn references (`CharacterSpawnReferenceObjectData`,
  `VehicleSpawnReferenceObjectData`) as entities;
* per blueprint: `EventConnections` (Source, Target, SourceEvent.Id, TargetEvent.Id, TargetType),
  `PropertyConnections` (Source, Target, SourceFieldId, TargetFieldId), `LinkConnections`, and the `Descriptor`
  (`InterfaceDescriptorData`: interface fields with constants);

objects and part of the schematics the Rush chain feeds (the park event's Predestruction is in layer34) [verified:
§13.3]. With it off, Metro RushLarge0 gives 125 scopes and 2,427 objects instead of 549 and 7,299 [verified:
`bf3dump mode`, census].

## 5. The graph (`logic_graph.h`)

### 5.1 Instantiation (plan §3.11, D12 revised; gap logic §2, §4)

1. Walk with `LogicWorld` (§4.1). One `LogicScopeInfo` per scope: parent, depth, reference GUID, `path` =
   hash_mix chain of reference GUIDs from the root (stable across runs and machines; never `hash_keyed`, whose seed
   is per process [verified: ids.h]).
2. One node per object that exists on this side (§5.2), in LogicWorld object order. `key` = hash_mix(path, entity
   GUID). Type from `logic_type_of(type_name)` (§6.1); references that remain objects (blueprint not instantiated)
   are Structural and get no edges.
3. Params: the fields the type reads (§6.2) as effective values; arrays flattened (`element` 0…n−1), bounded by
   `max_params`.
4. Edges: for each scope in walk order, for each connection array in entry order, resolve both ends to a node, an
   interface port of this scope (descriptor), or an interface port of a child scope (the child's reference).
   Interface ends become virtual IfaceIn/IfaceOut nodes per (scope, port):
   * parent `X.a → Ref.p` ⇒ `X.a → IfaceIn(s).p`; child `Desc.p → Y.b` ⇒ `IfaceIn(s).p → Y.b`;
   * child `Y.b → Desc.p` ⇒ `Y.b → IfaceOut(s).p`; parent `Ref.p → Z.c` ⇒ `IfaceOut(s).p → Z.c`;
   * child `Desc.p → Desc.q` ⇒ `IfaceIn(s).p → IfaceOut(s).q`.
5. Collapse: every path real → virtual* → real becomes one real edge, depth first in the order the hops were
   recorded, so the fan-out order is the connection array order of each hop [inferred; gap logic §5 does not fix
   BF3's order]. Each hop charges the budget; a port that expands to more than `max_fanout` edges, or a chain deeper
   than `max_interface_depth`, fails the build. Property paths that start at a descriptor constant with no parent
   driver become `LogicInput` (the constant, parsed by `PropertyValue::parse`, at start). Event TargetType is the
   last hop's (the hop into the real target) [inferred].
6. Sort each edge kind by (source, source port, order) and build CSR ranges per node; indices by GUID and by type.

The graph copies everything it keeps (no `EbxInstance` pointers), so it outlives the `LevelDatabase`.

### 5.2 Realm and routing (gap logic §3.4, §5)

* A node exists on the server when its realm is Server, ClientAndServer or unset (synced, gameplay and spatial types
  have no Realm field) [plan §3.11; gap logic §5]. Client-realm nodes are not created; edges touching them are
  dropped (`dropped_realm`).
* An event edge is delivered on the server when its TargetType is Server, ClientAndServer or
  NetworkedClientAndServer; NetworkedClient and NetworkedClientAndServer are also recorded as networked events
  (plan §3.5: {tick, connection index}); Client and Invalid edges are dropped (`dropped_target_type`) [inferred from
  the names, gap logic §3.4].
* The census tool applied these rules (skip ends with Realm_Client, skip TargetType Client / NetworkedClient /
  Invalid) to produce the server columns of §4.2 [verified].

### 5.3 Port ids

Port ids are `ebx_name_hash` (djb2-xor, i32), constexpr as `logic_port_id` [verified equal at run time:
`s4.contract`]. Verified on data: Out 193453899, OnTrigger 1975570652, Trigger −1688613187, OnDestroyed −1452333337,
OnPlayerEnter 1577401599, Enabled 2662400; EventSplitter in #1723395486 → out #−137490305; PlayerFilter out
#−1864525248; CompareInt out #193445146 [verified: scratch census port listing]. Designer interface ports have no
recoverable name (gap logic §3.5) and need none.

### 5.4 Digest

`digest()` = FNV-1a 64 over kLogicGraphVersion, kLogicTypesVersion and, in order: type names, keys, params, inputs,
edges. The plan §2.7 `sim_digest` includes it in M2b (the server and every client must run the same graph).

## 7. Runtime (`logic_runtime.h`)

* Tick t: due timers in (due tick, arm sequence) order → forced native outputs in call order → FIFO drain of one
  queue holding event and property items, to empty or `max_deliveries_per_tick` (10,000, plan §3.11), remainder
  carried to t+1 in order (counted, traced) [plan; carry-over inferred].
* Events fan out in edge order; a property output that changes (bitwise, `LogicValue::same_as`) queues one item per
  outgoing property edge with the value in the item, so a later change in the same drain cannot overtake an earlier
  one [inferred; gap logic §5 leaves same-tick propagation open, plan R15].
* Delay ticks = ceil(d × hz − 1e-3) in double. The epsilon is needed: Delay fields are float32, and 0.1f × 60 =
  6.0000001 would otherwise round up to 7 [inferred]. 10 s = 600 ticks.
* Init settle at tick 0: every node publishes its initial property outputs in node order, constant inputs are
  delivered, drain; then AutoStart nodes arm in node order and drain.
* Effects: every delivery into a Native node is a `LogicEffect` with apply tick t+1 (plan §2.3 "Enabled/spawn effects
  apply next tick").
* Events carry `LogicContext` {player, team} for TeamFilter / PlayerFilter; natives set it on their outputs.
* Trace: one record per delivery, timer fire, forced input, effect, carry-over and fault; hash = FNV-1a 64 over a
  fixed 40-byte little-endian encoding, portable across machines. Records kept only when asked.
* Ghost (plan §3.5): `LogicGhostLayout` lists SyncedBool nodes in (scope path, GUID) order (≤ 259 bits on retail
  [verified census max]), SyncedTransform (≤ 4 per row [plan]) and SyncedSequence start ticks. `LogicGhost` is a
  plain struct with `encode`/`decode` (full row) and `bool_delta` ((index u16, value) rows). Not networked in S4.
* The runtime is fault-tolerant, not exception-based: a fault stops further steps and returns its error.

## 9. Harness and scripts (`logic_harness.h`)

### 9.1 RushMcoms (Metro RushLarge0)

Structure found from the graph, never from GUIDs in code: MCOMs are StaticModel nodes whose OnDestroyed reaches a
MultipleTrigger with TriggerAmount 2 within 4 event hops; that MultipleTrigger is the base. Script: a Team1 and a
Team2 player enter at tick 1; when an MCOM's activation input (the crate's DelayTrigger Enabled, fed by the base
chain) arrives, its destruction is forced 3,600 ticks (60 s) later; run 10 min (36,000 ticks).

Wiring as verified (§13.3): round start → HumanPlayer OnPlayerEnter → Delay 1.0 s (RunOnce) → base 1 activation;
crates A and B OnDestroyed → EventSplitter → DelayTrigger (Enabled once armed) → MultipleTrigger (2, RunOnce)

## 10. Caching

None in S4. Load + walk + build is ≈ 0.2 s per row (§4.2) and the graph is cheaper to rebuild than to validate.
Reserved for later: Cache kind `logic-graph`, key = level source digest (`level/source_digest.h`, the level × mode's
manifest SHA1s) + kLogicGraphVersion + kLogicTypesVersion + side; blob = the graph's arrays. It would be added only
if M2b measures the build above 50 ms on its load path.

## 11. Hostile-input bounds

* Walk: LogicWorld's caps (depth 48, scopes 200 k, objects 4 M, walk steps 2 M, query steps 2 M) and one
  gameplay::WorkBudget of 1 M units for walk and build together [verified: logic_world.h; retail max 34,118].
* Build: every connection entry scanned, every interface hop, every param field and every node and edge emitted
  charges one unit; caps `max_nodes` 2^20, `max_edges` 2^22, `max_params` 2^22, `max_fanout` 2^16 per collapsed
  port, `max_interface_depth` 48. Collapse is depth-first with a visited set per start edge, so interface cycles
  terminate; total collapse work is bounded by the budget (superlinear fan-out fails with an error, never runs).
* Text: type names and scope names copied with the budget's byte charge; at most 1,024 listed type names.
* Runtime: `max_queue` 65,536, `max_timers` 65,536, `max_effects_per_tick` 65,536 → fault; `max_deliveries_per_tick`
  10,000 → carry-over; Sequence events per node bounded by params; trace records capped.
* `LogicGraph::Builder::finish` validates every index; `decode` of a ghost validates counts against the layout.
* `logic.fuzz` (§12) exercises these.

## 14. Risks and fallback rule

Plan R15: semantics wrong (ordering, re-entrancy, RemoveDuplicateEvents, Sequence timing, networked delivery) or a
primitive missing, so spawners or events misfire silently. Mitigations here: trace hash, the per-row census, gates
on exact ticks, and the stubs' timelines printed for review.

**Fallback (plan §6 S4 "fail → hand-written rules (old D12, option b) for those rows only"):**

| gate fails | rows that fall back | why those rows |
|---|---|---|
| G2 or G3 | MP_Subway RushLarge0 and SquadRush0 (both instantiate `full_rush_level`) | the base progression and the park event are that prefab's wiring; a hand-written Rush rule set (bases from the mode's MCOM objects, spawners by base) replaces the graph there, other Metro rows keep the interpreter |
| G6 | MP_007 ConquestLarge0 and ConquestSmall0 (same layer1 conquest layers) | the tank and IFV gating is that layer's wiring; a hand-written table (flag → spawner enable per team) replaces it |
| G5 on a row | that row only, until the missing type is implemented | an unknown or unimplemented type means the row's graph is incomplete |
| G1 on a row | that row | the graph cannot be built |
| G4 | none: a determinism failure is an interpreter bug, fixed before S4 closes | falling back would hide it, and every row would inherit it |
| G7 | none for the spike; the budget is revisited in M2b with the real server tick | a timing miss on a shared machine is not a semantic failure |

A failure is a valid S4 result: the report then gives the measured timelines and traces of the failing rows, which
is what the hand-written rules for those rows are written from.
